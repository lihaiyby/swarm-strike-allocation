## 0. 为什么需要改造（一句话背景）

现行模型下，**greedy 已经贴住 (a, b) 的理论天花板、用兵也贴着理论下界**，8 个待复现算法在 3n 编制下大概率只能比"耗时 e"，`a`/`b` 没有区分空间。核心不是"指标不够多"，而是**问题实例太简单**：资源不绑定、C3 空转、无时间耦合，导致"填满每波配额"即最优。

支撑数据（详见进度记录 §证据）：

| 观察 | 数值 |
|---|---|
| greedy 的 a / 理论配额天花板 | 589.7 / 590.4 = **99.9%** |
| greedy 的用兵 / 理论最少配额架数 | 357.0 / 358.0 = **99.7%** |
| 编制 3n 下 greedy 弃群次数 | **0**（结构性余量仅 6.2%，但仍够用） |
| 编制收到 2.5n 后 a 的效应量 | −0.62 → **+1.99**，且**排名翻转** |

**目标态**：每个算法都能被一条明确的轴拉开，且结论在难度换档后仍然可解释。

### 1.1 D2 的两因子拆解

"b 有几种口径"其实混了**两个彼此独立的选择**：

**因子甲：用什么"群"（K）**

| 选择 | 含义 | 稳定性 |
|---|---|---|
| A. 动态 DBSCAN | 每回合重聚类，噪点每回合领新 ID | ❌ 群 ID 抖动，分母随回合数膨胀 |
| B. 真值团 | 生成时的 `u.cluster`，固定不变 | ✅ 稳定、可跨算法比较 |
| C. 无群（逐机） | 每架敌机自成一群 | ✅ 稳定，但丢失"群"语义 |

**因子乙：怎么判"歼灭"（dead(k)）与如何加权**

| 选择 | 定义 | 性质 |
|---|---|---|
| 1. 全员阈值 | `dead(k) = ∧_{j∈k} [P_j ≥ 0.9]`，以 Σv_k 加权 | 0/1 阶跃，"一票否决" |
| 2. 仅 v≥5 | `dead(k) = ∧_{j∈k, v_j≥5} [P_j ≥ 0.9]` | 阶跃，但放行侦察机 |
| 3. 软化 | 不判定，直接 `Σ v_j P_j / Σ v_j` | **与 a 代数恒等**，不是新指标 |

通用公式：`b = Σ_{k: dead(k)} V_k / Σ_k V_k`，其中 `V_k = Σ_{j∈k} v_j`。

组合后只有 7 个互不相同的候选，其中 **B1（真值团 + 全员阈值）**是唯一同时满足"稳定、非退化、保留群语义"的一个。

**A 为什么不稳定——实测（seed 1000，同一场景换算法）**

| 算法 | 求解回合 | 换过群的敌机 | 累计群 ID 数 / 真实团数 |
|---|---|---|---|
| greedy | 3 | **0%** | 21 / 21 = **1.00×** |
| ga_iap | 6 | **24%**（26/110） | 53 / 21 = **2.52×** |

典型例子：侦察机 `#43` 三回合分别属于群 `18 → 30 → 38`；`#45` 为 `19 → 31 → 39`。
**漂移几乎全部发生在"留下来的侦察机"身上**——也就是 b 本来要惩罚的那批目标，反而在分母里被重复计入。
机制与复现方法见进度记录 2026-10-23 条目。
