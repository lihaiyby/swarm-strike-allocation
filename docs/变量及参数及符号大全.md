## 0. 阅读约定

- **环节**列取值：`场景` 场景生成 → `感知` 分组与威胁评估 → `可行` 可行性恢复 → `算法` 求解 → `结算` 毁伤与战损 → `评估` 指标 → `实验` 统计出图。
- **状态**列：`生效` = 当前真正被调用；`闲置` = 定义了但无人调用（见 §10）；`未用` = 配置项从未被读取。
- 代码位置一律相对 `src/swarm_alloc/`。

## 1. 数学符号（《统一模型文档v1》层）

| 符号 | 含义 | 取值 / 计算 | 对应代码 | 环节 |
|---|---|---|---|---|
| `I` | 我方可用资源池（不含已冻结） | `state.pool` 的键集合 | `State.pool` | 算法 |
| `J` | 当前在空的敌方目标集合 | `state.enemies` 的键集合 | `State.enemies` | 算法 |
| `K` | 敌群集合 | `DBSCAN(J)`，噪点独立成群 | `GroupTracker.groups` | 感知 |
| `J_k` | 敌群 k 内的目标 | `Group.member_ids` | `Group.member_ids` | 感知 |
| `I_k` | 与敌群 k 配对的我方编组 | **框架从未构造**（见 §10） | — | — |
| `R` | 战场半径 | 3000 / 4000 / 5000 m，按场景序号轮换 | `Scene.R` | 场景 |
| `T` | 战局总时长 | `T = R / enemy_max_speed_mps` = R/50 s（即 60/80/100 s） | `Scene.T` | 场景 |
| `n` | 单个场景敌机总数 | 100~150 随机 | `Scene.n_enemy` | 场景 |
| `v_j` | 敌机 j 的价值 | `{2, 5, 10}`，比例 3:5:2 | `EnemyUnit.value` | 场景/评估 |
| `p_j` | 我方单机对 j 的毁伤概率 | 机动 10/5/2 → `0.4 / 0.7 / 0.9` | `EnemyUnit.p_kill` | 全局 |
| `q1` | 格斗型单点杀伤概率 | `0.2` | `enemy_types.yaml` → `lethality.q` | 结算 |
| `q2` | 范围伤害型杀伤概率 | `0.5` | 同上 | 结算 |
| `r` | 范围伤害半径 | `100` m | `lethality.radius_m` | 结算 |
| `w_k` | 敌群 k 的威胁度 | 熵权-TOPSIS ∈ [0,1] | `Group.threat` | 感知/可行 |
| `P*` | 歼灭阈值 | `0.9` | `Model.kill_threshold` | 结算 |
| `m_j` | 目标 j 的打击配额（达到 P* 所需最小架数） | `⌈ln(1-P*)/ln(1-p_j)⌉` → 5 / 2 / 1 | `Model.quota()` | 可行/算法 |
| `x_ij` | 决策变量：我机 i 打目标 j | 0-1 | 分配矩阵 `X[i,j]` | 算法 |
| `X` | 完整分配方案 | `(len(pool_ids) × len(enemy_ids))` 的 0-1 矩阵 | `AlgoBase.solve` 返回值 | 算法 |
| `P_j(k)` | 累积毁伤概率 | `1 − (1−p_j)^k` | `Model.damage()` | 结算 |
| `f(X)` | 目标函数（= 指标 a） | `Σ_j v_j · P_j` | `Model.objective()` **闲置** | — |

### 约束 C1~C5

| 编号 | 含义 | 代码是否强制 |
|---|---|---|
| `C1` | 单架单目标，`Σ_j x_ij ≤ 1` | ✅ `Model.check`；⚠️ 仿真主循环不调用 |
| `C2` | 打则必达配额：`Σ_i x_ij = 0` 或 `≥ m_j` | ✅ 同上 |
| `C3` | 群对群：编组 I_k 只能打 J_k | ⚠️ 分支存在但 `group_of_friendly` 从未构造 → **永空转** |
| `C4` | 编组内我机数 ≥ 敌群目标数（确保多打一） | ❌ 文档有、代码无 |
| `C5` | 冻结机不可分配 | ✅ `Model.check`；仿真中 `frozen_ids` 恒为空 |

### 5.3 结算（`simulation/settle.py`）

```python
battle_damage(rng, engaged_enemies, pool, type_lethality) -> list[loss_ids]
```
- `point` 模式：以概率 `q` 击落池中**离该敌机最近**的 1 架；
- `area` 模式：半径 `radius_m` 内的每架我机各以概率 `q` 损失。

## 6. 感知层（`perception/topsis.py`）

| 名称 | 含义 |
|---|---|
| `M` | 决策矩阵 `(群数 × 3)`：`[总价值, 平均速度, 最近距离]` |
| `M_pos` | 正向化后矩阵：价值↑、速度↑、距离取负（越小越危险） |
| `w` | 熵权法权重 `entropy_weights(M_pos)` |
| `V` | 加权归一化矩阵 |
| `v_best` / `v_worst` | 正/负理想解 |
| `d_best` / `d_worst` | 到正/负理想解的欧氏距离 |
| `score` | 威胁度 `d_worst / (d_best + d_worst)` → 写入 `Group.threat` |

> ⚠️ 方案原文要求 4 个特征（总价值、**机动能力**、速度、距离），实现只用了 3 个，`maneuver` 未参与。

### 指标 a~e 速查

| 代号 | 名称 | 计算 | 产出位置 |
|---|---|---|---|
| **a** | 打击总收益 | `Σ_j v_j · P_j`（期望值口径，不掷骰子） | `BattleResult.a_gain` |
| **b** | 威胁消除率 | `Σ(被歼群威胁) / Σ(全部群威胁)`；群内**全部**成员 `P_j ≥ 0.9` 才算被歼 | `BattleResult.b_threat` |
| **c** | 稳定性 | 各指标在 50 场景上的标准差 | `exp1_summary.csv` |
| **d** | 效费比 | `a / 出动架数`（单机价值硬编码 1） | `BattleResult.d_cost` |
| **e** | 求解效率 | 单次分配平均耗时，参考上限 1 s | `BattleResult.time_s` |

> ⚠️ **b 的分母当前不稳定（待 P0.1 修复）**
> `threat_total` 累加的是"历次**新出现**群的威胁"，而 `GroupTracker` 对噪点每回合发放**全新 ID**，
> 于是同一架幸存敌机会被重复计入分母。实测（seed 1000）：greedy 累计群 ID 21/真实团 21 = 1.00×，
> ga_iap 为 53/21 = **2.52×**；换群的全部是侦察机（`#43` 的群 ID 序列为 `18→30→38`）。
> 另外 TOPSIS 威胁度是**每回合在当轮群集合内归一化**的，跨回合求和本身也不成立。
> 详见进度记录 2026-10-23 条目与任务清单 D2。

> ✅ **e 的"墙钟截断"污染已修复（P0.3，2026-10-25）**
> `ga_iap` 现以**固定 200 代**为唯一停止条件，`TIME_BUDGET_S` 默认 `None`。
> 实测：同一 `state` 连解 5 次 `X` 逐位相等；同 seed 完整仿真空载 10 次、CPU 满载 10 次，
> `(a, b, used, destroyed)` 各只有 1 个唯一结果，且满载 == 空载。
> **但仍有一条限制**：e 现在测的是"跑满 200 代的时间"，依然随机器变
> （空载 0.72~0.79 s/轮，满载 0.93 s/轮，已逼近 1 s 上限），
> 因此 **e 只能同机跨算法比较，不能跨机器比较**。
> 若需复现旧行为（限时解），须显式设 `TIME_BUDGET_S`：实测 0.10 s 连解 3 次得
> 28/31/34 代、3 个不同解，`truncated=True` 可识别——**该模式结果不可复现**。
