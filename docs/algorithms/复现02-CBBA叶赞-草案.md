## 0. 修订说明（第一版是错的）

第一版在**没有原文**的情况下，按摘要"任务包双向构建 + 类别奖励"猜了两处实现：
把"双向"理解成"正向拍卖 + 反向释放重拍"，把"类别奖励"理解成"高价值类别加成"。

拿到原文后发现**两处都猜错了**：

| | 第一版（猜测） | 原文实际 |
|---|---|---|
| 双向构建 | 正向拍卖 + 反向释放重拍 | 正向从机巢出发构建 / **反向以机巢为终点追溯**，两者进**候选池**，再用整数规划选优 |
| 类别奖励 | 高价值类别加成 | **K-means 区域聚类** + 同区域奖励（人工势场思路） |
| 遗漏的第三处 | — | **风机巡检价值评估函数**（风速代价 + 高度代价） |

**后果很严重**：猜测版在 normal 档综合分 **1.0137（第 1 名）**，忠实版只有 **0.9989（第 3 名）**。
猜测无意中"美化"了这个算法。这正是复现必须依据原文的原因。

## 一、原文的三处改进

### 1.1 价值评估函数（式 1~3）

$$W = W_0 - (\lambda W_1 + \mu W_2)$$

- $W_1$ **风速代价**：$\sum \text{Dis}\cdot\dfrac{v_a^2-(v_{fx}\cos\theta_a+v_{fy}\sin\theta_a)^2}{v\cdot L_{\max}}$
- $W_2$ **高度代价**：$h_f - h_a$
- $\lambda=0.6$（水平耗电比重）、$\mu=0.4$（升高耗电比重）

**动机**：传统 CBBA 用时间折扣因子算收益，而巡检任务价值与时间无关；同时风速/海拔显著影响能耗。

### 1.2 任务包双向构建

- **正向**：以无人机初始机巢为起点，按"**价值优先、能耗可控**"依次添加任务，直到任务包达容量上限或剩余任务超出满电航程。
- **反向**：以风电场内**所有机巢为潜在终点**，反向追溯可覆盖的任务点，形成"任务集合—终点机巢"组合。
- 两类包分别校验**最大航程 / 容量 / 无冲突**三大约束，合格者进**候选任务包池**。

**动机**：考虑返程需求，实现"机巢—任务包—机巢"全路径能耗最优。

### 1.3 基于类别的奖励制度（式 4~5）

- 先用 **K-means** 对风机任务点与机巢聚类，划分巡检区域；
- 借人工势场法的引力/斥力思路，**同类任务给奖励、异类无奖励**：

$$G=\begin{cases}\zeta/2\cdot d^*, & C_p=C_q\\ \eta/2, & C_p\ne C_q\end{cases}$$

- 总收益：$SP_i=\sum_p W_{pi}+G_{pi}$

**动机**：减少无人机长距离跨区域飞行，降低整体能耗与完成时间。

### 1.4 五阶段流程

初始化 → **双向任务包构建** → **任务共识** → **最优组合筛选（整数规划）** → 结束判断（不满意则回到双向构建迭代）。

## 二、移植到本项目的适配（逐条对照）

| 原文设定 | 本项目 | 处理方式 |
|---|---|---|
| 价值含风速/海拔代价 | 无风场、无海拔、**不建模飞行** | **不移植**。价值直接取场景给定的 $v_j$（10/5/2） |
| 每机任务包容量 4 | **每机只能打一个目标**（C1，自杀式） | bundle 退化为单槽；"容量"改指**目标的配额** $m_j$ |
| 机巢 4 个 + 航程 45 km | 我方全部署在内球面，**无航程约束** | 正向池 = 每目标取**最近**的 $k$ 架；反向池 = 取**离部署中心最近**的 $k$ 架（返程最省） |
| **整数规划确定最优任务组合** | 同 | **槽展开 + 最大权二分匹配**（`scipy.linear_sum_assignment`）——见 §3 |
| K-means 分区 + 同类奖励 | 目标有空间分布 | **照做**：对目标坐标 K-means，同区奖励 |
| 收益量纲 = 能耗 kWh | 量纲 = 价值 2~10 | $\zeta,\eta$ 按 $v_j$ 归一化，否则奖励被量纲淹没 |

**唯一"不移植"的一项**是价值函数——它依赖风电场特有的风速与海拔，本项目没有对应物。
这是**场景差异**，不是实现偏差，已在适配对照表中显式记录。

## 三、实现要点：原文的"整数规划"在本项目可精确求解

原文用整数规划从候选池中挑最优组合。本项目可以**精确求解**，这是一个有意思的对应：

把目标 $j$ 展开成 $m_j$ 个**槽**，第 $s$ 个槽的边际价值为

$$m_{j,s}=v_j\,p_j\,(1-p_j)^{s},\qquad s=0,1,\dots,m_j-1$$

因为 $P_j(k)=1-(1-p_j)^k$ 是凹函数，"带容量约束的最大权分配"就等价于
**在槽上的最大权二分匹配**——把 $n$ 架机与 $\sum_j m_j$ 个槽配对，收益为
$m_{j,s}+G_{ij}$，用 LSA 一次求出精确最优。

**这个结构保证了：若不加任何额外约束，算法必然达到"按边际收益填满配额"的最优解。**

## 五、消融与"为什么等于 greedy"

### 5.1 两处改进的消融（normal 档，30 场景）

| 配置 | a_kill | b | d | gap | 耗时 |
|---|---|---|---|---|---|
| 全部（原文） | 588.10 | 0.8866 | 1.7090 | 0.0796 | 0.014 s |
| 无类别奖励（ζ=η=0） | 588.10 | 0.8850 | 1.7090 | 0.0796 | 0.014 s |
| 无双向池（全可行） | **588.43** | **0.8901** | 1.7092 | 0.0791 | 0.011 s |
| 两者都关 | **588.43** | **0.8901** | 1.7092 | 0.0791 | 0.009 s |

### 5.2 三条发现

**① 类别奖励几乎无影响**（a_kill 完全不变，b 仅 +0.0016）

因为本项目**我方同质、距离不影响毁伤**：奖励只改变"哪架机去打哪个目标"，
不改变各目标分到几架。只有当资源极度稀缺、槽位需要竞争时，奖励才会改变分配结果。

**② 双向候选池是有害的**（去掉后 a_kill +0.33、b +0.0053）

候选池等于人为限制"每目标只能由最近的 k 架机打"。在本项目里距离不影响毁伤，
这个限制纯属损失——它把好机子挡在门外，导致某些目标的配额凑不齐。

**③ "两者都关"的结果与 greedy 逐位相同**

`588.43 / 0.8901 / 1.7092` 正是 greedy 在同一组 30 场景上的数字。
原因见 §3：**槽展开的最大权匹配 = 按边际收益填满配额 = greedy 的取值规则**。
在我方同质、距离无关的模型下，这是理论上的最优，任何"正确"的分配算法都会收敛到它。

> **这解释了为什么 `cbba_ye` 打不过 `ga_iap`**：`ga_iap` 赢在**跨波次预算**
> （第二目标是"最小化出动架数"），而不是单轮分配更聪明。单轮内谁都能做到最优；
> 差别在于**这一轮该花多少兵**——那是 CBBA 家族（按当前态势最大化收益）结构上不具备的。

### 5.3 这对平台意味着什么

> 在本项目的约束结构下（一机一目标、同质、无航程、距离不影响毁伤），
> **单轮分配问题的难度被压得很低**，`greedy` 就已经逼近最优（easy 档 gap 仅 0.08%）。
> 算法之间的差异几乎全部来自**跨波次的兵力预算**，而不是"这一轮怎么分"。

这条结论同时解释了此前观测到的多个现象：`myopic_opt`（每轮最优）全场景平均只有 greedy 的 37%；
以及"资源越紧、`ga_iap` 越占优"的灵敏度结果。

## 七、结论

1. **A1 复现完成**，机制按原文实现，C1/C2 全量复检 0 违规，耗时 0.011~0.018 s/场。
2. **在三档 50 场景上，`cbba_ye` 与 `greedy` 的差异在 0.2% 以内**；综合分名次 easy 2 / normal 3 / hard 3。
3. **两处改进在本场景几乎不起作用**：类别奖励因"同质 + 距离无关"而失去作用对象；
   双向候选池反而是纯损失。第三处改进（价值函数）因场景差异无法移植。
4. **结构性解释**：单轮分配在本项目中可被槽展开的最大权匹配**精确求解**，而该解就等于 greedy 的取值规则。
   算法差异来自跨波次预算，`ga_iap` 因此占优。
5. **这本身是一条有价值的平台结论**：复现文献算法时，若其改进点依赖本场景不存在的物理细节
   （能耗、航程、飞行时间），迁移后会退化。这应当写进技术报告的"算法移植性"一节。
